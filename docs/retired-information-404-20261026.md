# Return current 404s for retired information routes

The disclosure and regions sections were deleted in all languages. Source and static exports contain no such pages. Nevertheless, ordinary custom-domain requests still returned six stale RU/ES HTTP200 responses after verified deployments, URL/zone purges, an authorized short Development Mode test and an authorized DNS Only test. Both diagnostic settings were restored. We have not established Cloudflare's exact internal caching cause.

This change makes the intended HTTP404 behavior explicit before the retired asset-serving path. A Cloudflare Pages Function is invoked only for disclosure/regions URL scopes in RU/EN/ES, including their slash variants and descendants. The `_routes.json` include list contains exactly12 bounded patterns. Active pages, images and RSC payloads remain static and do not match these invocation routes. A second path-boundary check inside the handler passes unrelated paths through unchanged.

For matching requests the handler reads the current build's localized pretty-path 404 asset through `env.ASSETS.fetch`. An explicit English404 avoids rendering a Russian shell before English hydration on a retired EN URL; it remains noindex and outside the sitemap, alongside the existing RU/ES error pages. It never fetches the retired path. Visitor cookies, authorization, conditional headers and query parameters are not forwarded. The result is always404 with `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow` and the existing security policy. Old Age, ETag, redirects and cookies are not propagated. HEAD is bodyless. A fixed localized safe404 is available if the error asset cannot be read. A response marker allows deployment verification to distinguish the Function from a coincidental static404.

This compensates for stale retired responses; it does not claim to purge the upstream cache. It is a correctness handler, not an authentication boundary. Only matching retired requests use the Pages Functions allowance; active static requests retain their existing serving path. No new package dependencies, secrets, external fetch destinations or bindings are introduced. GitHub Pages continues returning its existing static404; it does not execute Pages Functions.

Seven regression tests cover route/asset configuration, every retired URL, security/header preservation, bodyless HEAD, isolation of query/auth/conditional data, asset failure, unchanged active/similarly named routes, and localized 404 hydration and home navigation. Existing removed-route tests keep `maxRedirects: 0` and require404; no redirect or soft404 is accepted. Existing CI, artwork, data and SEO checks are unchanged. The Cloudflare build additionally requires the exported invocation manifest.

Before opening indexing, verify the exact final CI and preview, then ordinary custom-domain URLs: all nine deleted URLs must return404 without redirects, the response marker and no-store. Verify unrelated pages, assets, language navigation, the catalogue payload rewrite and the security policy remain intact. Indexing is not enabled by this change.

References: [Functions routing](https://developers.cloudflare.com/pages/functions/routing/), [ASSETS binding](https://developers.cloudflare.com/pages/functions/api-reference/), [header behavior for Functions](https://developers.cloudflare.com/pages/configuration/headers/).
