# Проверка готового каркаса

## v124 — 1win-верифицированное расширение

7 сентября 2026. Каталог расширен до **41 игры**, **8 провайдеров** и **5 механик**. Добавлены 11 слотов, каждый содержит внутреннюю запись доступности 1win с датой `2026-09-07` и ссылкой на официальный сайт или официальный форум 1win. Уникальность slug, связь с профилями провайдеров, поддерживаемые механики и наличие редакционных tags проверяются отдельно.

Тестовые ожидания обновлены под порционную выдачу 41 игры: 18 → 36 → 41. Счётчики профилей больше не зашиты числами и вычисляются из `slots`, `providerProfiles` и `mechanics`. Добавлен data-level тест, который считает 30 игр v123 исторической базой и автоматически требует 1win-свидетельство для каждой новой игры после неё. Сейчас это 11 slug v124; будущая партия тоже не пройдёт проверку без источника 1win.

Manifest изображений содержит 42 записи: 31 локальный WebP уже находится в репозитории, 11 новых файлов должны быть локализованы до сборки. В GitHub Pages workflow для этого добавлен явный `npm run assets:localize`, а готовые изображения и source-cache сохраняются через Actions cache. В текущем контейнере Node не имеет исходящего сетевого доступа, поэтому локальную загрузку этих 11 бинарных файлов не выдаём за выполненную.

Полный `npm run build` для v124 не заявляется до успешной локализации новых изображений и установки проектных зависимостей в подходящем окружении. В текущем контейнере отдельно прошла строгая компиляция изменённых `src/lib/*` через TypeScript 5.8 с `moduleResolution=bundler`, `node --check` локализатора изображений, проверка JSON manifest и data-level прогон: 41 уникальный slot slug, 8 профилей провайдеров, 5 механик, 11 новых записей с 1win-свидетельством, 42 записи manifest и корректные новые поисковые алиасы.

## v123 — масштабирование каталога и медиаслоя

7 сентября 2026. Каталог отделён от полного массива досье: сервер формирует компактную модель, facets считаются заранее, клиентская фильтрация вынесена в чистый модуль и мемоизирована. Сравнение ограничено двумя играми и больше не тянет `data.ts` через каждую кнопку.

Доступный полный `tsc --noEmit` проходит. `node --check scripts/localize-slot-images.mjs` проходит. Отдельно скомпилированы и выполнены data/query/index-модули: текущая модель содержит 30 игр, 7 провайдеров и 5 механик; синтетический каталог на 5000 записей корректно проходит комбинированный фильтр и сортировку. Это sanity-check, а не обещание фиксированного времени на каждом устройстве.

Медиаслой проверен отдельно: 31 запись `docs/image-sources.json` имеет существующий локальный WebP; превышений лимита 960×540 для обычных обложек и 1200×630 для feature-графики нет. Общий вес актуальных игровых WebP — около 1,16 МиБ. Удалены старые дубли из `public/images`. Production build теперь не выполняет сетевую локализацию: `prebuild` только проверяет уже подготовленные файлы.

Полный `npm run build` повторно не заявляется. Единственный доступный набор `node_modules` создан Astra под Windows и не содержит Linux optional packages для TypeScript 7/Sharp/Next SWC; сети для нормального `npm ci` в текущем окружении нет.

## v122 — профили и системный аудит

7 сентября 2026. Astra выполнила основной браузерный и screenshot QA новых профилей провайдеров и механик, после чего была внесена финальная правка fallback для игровых изображений. В текущем Linux-окружении повторный `npm run build` не удалось выполнить из-за платформенных optional dependencies из Windows-архива (`sharp`, `@next/swc-*`) и отсутствия доступа к npm registry. Успешную финальную сборку поэтому не заявляем повторно.

Повторно выполнены доступные проверки исходников: `npm run typecheck` проходит; шесть data-level Playwright тестов проходят, включая таксономию, поиск, RTP, расширенные досье и все 4060 комбинаций из трёх игр. Основной браузерный прогон и скриншоты, выполненные Astra до исчерпания её квоты, сохранены только как рабочее свидетельство и не включаются в чистые архивы.

7 сентября 2026. Последний полный production-прогон с Playwright относится к v117/v118. Для v119/v120 в текущем окружении нет установленных npm-зависимостей, поэтому полный `npm run build`, проектный typecheck и браузерные тесты повторно не запускались. Для v120 выполнены отдельная компиляционная проверка `src/lib/data.ts`, синтаксический разбор всех изменённых TS/TSX через TypeScript `transpileModule`, проверка таксономии 30 игр и логики поиска/связанных игр.

- `npm run typecheck` — успешно.
- Предыдущий полный `npm test` — **7 тестов прошли**, итоговый прогон 20 секунд. В v118 добавлен восьмой тест локальности игровых изображений; полный сетевой прогон v118 в текущем контейнере не выполнялся.
- После финальной правки размеров заголовка GEO, подвала на 320 px и изображений сравнения повторно прошли 2 затронутых сценария: все размеры viewport и реальная прокрутка к якорю статьи (10,4 секунды). Production-сборка повторно успешна.
- В предыдущем полном прогоне был проверен 31 публичный маршрут. В v119 число динамических страниц выросло вместе с каталогом; полный HTTP-обход новой матрицы маршрутов ещё не повторялся.
- Внутренние ссылки, включая отфильтрованные URL, и все ссылки на локальные изображения проверены HTTP-запросами.
- Ошибок JavaScript при обходе страниц нет.
- Переполнения viewport нет на 320, 390, 768, 1024 и 1440 px для главной, каталога, досье, статьи, подборки и GEO.

## Сценарии

1. Запрос `bonanza` → две игры; фильтр Play’n GO → пустая выдача; сброс → первые 18 из 30 игр, затем `Показать ещё 12`.
2. Каскады + сортировка по названию сохраняются при перезагрузке; режим обложек переключается.
3. Две игры добавляются в сравнение; третья показывает ограничение; выбор сохраняется; удаление освобождает место для новой пары.
4. Мобильное меню открывает второй уровень и закрывается после перехода; мобильные фильтры раскрываются; FAQ открывается.
5. Поисковый URL восстанавливает провайдера и сортировку; оглавление длинного материала ведёт к существующим разделам.
6. Неизвестные страницы, игры, провайдеры, механики и операторы возвращают 404. Неподключённый `/go/1win` перенаправляет на /about.
7. Проверена ширина страниц в пяти размерах viewport.

Снимки главной, каталога, профиля игры, длинного материала и подборки созданы на desktop 1440×1000, tablet 768×1024 и mobile 390×844. Просмотрены основные композиции, длинная полоса статьи и мобильное досье. Дополнительно сохранены пустая выдача, открытые фильтры, сравнение, мобильное чтение и GEO на 320 px.

После первого просмотра исправлены растягивание мобильной иллюстрации, качество основной игровой обложки и пробел в заголовке desktop. После функционального прогона исправлены повторный H1, статус неизвестных динамических адресов и перенос длинного заголовка.

## Практические границы

Это завершённый визуальный и структурный фундамент, пока не опубликованный как полноценный сайт. CMS, промышленная пагинация/индекс поиска, матрица доступности операторов по странам, реальные рекламные предложения и редакционные контакты ещё не подключены. Числа RTP отмечены как справочные и требуют редакционной проверки конкретной версии. Для v118 добавлены статические проверки локальных путей изображений и runtime-проверка отсутствия внешних `<img>`. Синтаксис build-time скрипта проверен через `node --check`. ## Refinement 10 — таксономия и фильтры

Для v120 у всех 30 игр проверено наличие основной механики в массиве `mechanics`, минимум трёх нормализованных особенностей и числового справочного RTP. В каталоге 12 игр теперь относятся к каскадам, 15 к линиям, 7 к кластерам, 4 к сбору символов и 4 к способам; одна игра может входить в несколько групп. Поиск отдельно проверен на русские алиасы `РТП` и признаки из `tags`. Алгоритм связанных игр возвращает уникальные записи и не включает текущую игру.

Полный `tsc --noEmit` в текущем контейнере ожидаемо останавливается на отсутствующих локальных пакетах Next/React/Playwright и их типах. Это ограничение окружения, а не успешный проектный typecheck. `src/lib/data.ts` при этом проходит самостоятельный `tsc --noEmit`, а изменённые TSX-файлы проходят синтаксический разбор TypeScript. Полный build и Playwright остаются финальной проверкой в окружении с `npm ci`.
